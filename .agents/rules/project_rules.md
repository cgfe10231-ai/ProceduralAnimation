# ProceduralAnimation - Project Rules (.agents/rules)

## 1. 项目核心定义与技术方向
* 本项目为**全程序化 3D 连续动画生成系统**。
* 核心技术栈：Blender + Python (Blender Python API `bpy`)。
* 采用可从命令行/后台无头 (Headless) 自动运行的管线架构。
* 所有生成逻辑必须基于固定随机种子以保证 100% 可复现性。
* 当前美术风格尚未最终确定，阶段 1 采用简单人形占位模型，禁止擅自固定或锁定最终视觉风格。
* 禁止将项目降级简化为局部几何体演示、粒子 demo、单镜头测试或静态场景生成器。

## 2. 文件保护与隔离约束
* 必须在当前独立目录 `ProceduralAnimation/` 内工作，禁止修改、移动、删除或覆盖任何项目外部文件。
* 严禁触碰任何相邻工程（包括 Unity 项目、桌面课程实验文档、其他已有代码和个人数据）。
* 在执行任何删除、重命名、覆盖或大范围文件修改前，必须先列明影响范围。
* 遇任何不确定文件，默认视为保护对象，严禁修改。

## 3. 事实与验证纪律（核心原则）
所有任务状态汇报必须严格区分以下 6 种状态，严禁模糊或混淆：
1. **已实现**：代码或配置已编写完成。
2. **已执行但未完整验证**：已运行但未逐项核对输出、日志或文件实际内容。
3. **已验证**：已实际运行并针对产物（文件存在、无报错、尺寸/帧数/内容正确）进行真实检查确认。
4. **未实现**：尚未编写或构建。
5. **已知缺陷**：已发现的 bug、告警、不一致或限制。
6. **理论可行但尚未测试**：逻辑推测可行但尚未在真实环境中执行测试。

**绝对禁止**把以下情况声称或汇报为“完成”：
* 代码写了但未实际运行；
* 命令运行了但未检查返回码与输出；
* 文件声称生成了但未实际检验其存在与内容；
* Blender 脚本未实际被 Blender 引擎执行；
* 渲染未产生实际输出媒体文件；
* 仅凭代码逻辑推测结果正确。

## 4. 任务生命周期执行协议 (Task Lifecycle Protocol)
* **每次开始任何新任务前**：
  1. 读取项目规则 (`GEMINI.md` / `AGENTS.md`)。
  2. 读取 `PROJECT_SPEC.md`。
  3. 读取 `ARCHITECTURE.md`。
  4. 读取 `ARCHITECTURE_SYNC.md`。
  5. 读取 `DECISIONS.md`。
  6. 读取 `PROJECT_STATE.md`。
  7. 读取 `HANDOFF.md`。
  8. 读取 `AI_SYNC.md`。
  9. 执行 `git status --short`，检查已有修改并严格保留现场，确认用户当前任务是否与已有工作冲突。
  10. 检查当前相关代码与依赖。
* **每次结束任何任务前**：
  1. 检查实际修改内容与新增文件差异（`git status --short` / `git diff`）。
  2. 执行适当的真实验证。
  3. 如实记录测试结果（区分已验证、未验证、失败）。
  4. 更新 `PROJECT_STATE.md`。
  5. 更新 `CHANGELOG.md`。
  6. 有重要新决策时更新 `DECISIONS.md`。
  7. 更新 `HANDOFF.md`。
  8. 更新 `AI_SYNC.md`（并在交接卡片中包含 Git 状态、commit SHA 及未提交文件说明）。
  9. **Git 自动收尾提交与远程同步**：任务完成并通过验证后，针对本任务相关的源代码、测试、必要配置与文档创建本地 Git commit，随后自动安全推送到远程仓库（`git push origin master`），验证远程分支 HEAD 与本地 commit SHA 一致，并在 `AI_SYNC.md` 记录最终同步状态。
* **中断与失败一致性**：若任务中断或验证失败，严禁伪装成功提交；必须保留现场并如实报告失败/中断状态。

## 5. 防止项目状态漂移原则 (Anti-Drift Principles)
* **真实代码为准**：磁盘上的实际代码与可复现测试结果，是判断实现状态的首要依据。
* **文档层级关系**：
  * `PROJECT_SPEC.md` 记录已经确定的需求。
  * `DECISIONS.md` 记录已批准的重要决策。
  * `PROJECT_STATE.md` 记录当前核实后的工程状态。
  * `HANDOFF.md` 与 `AI_SYNC.md` 属于摘要，**不得覆盖上述原始事实**。
* **冲突处理**：遇到文档和代码不一致时，不得自行假定哪一方正确，必须调查并记录冲突。
* **禁止无据变更**：不得因为聊天记录缺失而擅自改变项目目标。
* **无法恢复即标记未知**：无法恢复的上下文应明确标记为未知，不得编造。
* **禁止脑内重构**：不得在没有检查项目文件的情况下，根据聊天记忆直接重构系统。

## 6. 修改与审批纪律
* 小型、局部、可逆修改可自行完成，但修改前必须检查依赖与调用关系。
* 重大操作（大规模重构、删除文件、更换技术栈、引入付费API或大型外部依赖）必须事先报批。

## 7. Git 版本控制与自动收尾纪律 (Git Lifecycle Rules)
* **任务前现场检查**：每个开发任务开始前必须执行 `git status --short`，确认工作树状态并保留现场未提交修改，严禁覆盖或丢弃。
* **精确暂存与审查**：Git 提交前必须检查新增文件和改动差异（`git status` / `git diff`），严禁直接使用盲目的 `git add -A` 或 `git add .`。只暂存与当前任务直接相关的源码、测试、配置与文档。严禁提交密钥、环境私密信息、临时测试脚本、缓存文件或未受控的大型二进制渲染资产。
* **验证通过后方可提交**：只有当所有验证实际通过、产物核实无误且 `PROJECT_STATE.md`、`AI_SYNC.md` 等文档已更新后，方可创建本地 commit。
* **规范提交信息**：提交信息必须明确标注任务编号及简要改动内容（例如 `feat(task-6b): implement procedural running action in unified motion framework`）。
* **失败与中断严禁提交**：测试未通过、运行报错或任务中断时，绝对禁止创建虚假成功提交；必须如实记录真实失败状态并保留工作现场。
* **自动化安全同步推送与历史保护**：
  * **自动化安全远程同步**：在所有验证通过并创建本地规范 commit 后，**必须自动执行 `git push origin master`** 将更改同步至 GitHub 远程仓库，并立即验证远程最新 commit SHA 与本地 HEAD 一致。严禁遗漏远程推送。
  * **严禁强制推送与破坏性清理**：**严禁执行 `git push --force`**、**严禁执行 `git reset --hard`**、强制清理（`git clean -fd` 破坏未审查文件）。
  * **禁止擅自改写历史**：**禁止擅自 `git commit --amend`、`git rebase` 或以任何方式改写已有提交历史**。
* **交接卡片透明化**：在最终生成的 `AI_SYNC.md` 及报告中，必须明确记录当前本地 Git 状态、最新 commit SHA 以及是否有未提交文件或遗留变动。

## 8. 永久架构门禁与防伪造纪律 (Architecture Change Gate & Anti-Fabrication Rules)
* **单一权威规范来源 (SSOT)**：所有架构变更准入、行为清规与偏差报批，以 [`docs/ARCHITECTURE_CHANGE_GATE.md`](file:///c:/Users/64701/OneDrive/Desktop/ProceduralAnimation/docs/ARCHITECTURE_CHANGE_GATE.md) 为唯一权威标准。
* **架构变更前置 11 问清单 (Pre-flight Checklist)**：任何新功能或重构开发前，必须明确：
  1. 已有实现与可复用模块排查；
  2. 唯一层级职责；
  3. 真实调用者（Caller）与被调用者（Callee）；
  4. 接入单帧 6 阶段执行协议的哪一阶段（Phase 1 至 Phase 6）；
  5. 输入参数与输出数据结构合同；
  6. 物理世界坐标空间（+Z Up, Ground Z=0.0m）及单位（m, deg, s）；
  7. 状态与控制器独占读写所有权（严禁多模块写竞争）；
  8. 对历史成熟动作（Walk/Run/Sprint/Brake）的零退化影响；
  9. 必须运行的自动化回归测试级别（`quick` / `physics` / `motion` / `full`）；
  10. Blender GUI 视口真实目视验收方式；
  11. 若未接入主执行链，明确其作为独立数学基础模块的定位、未来接入节点及隔离边界（允许经登记的只读数学模块独立存在）。
* **八大绝对清规 (Strict Prohibitions)**：
  1. 严禁通过复制代码或私写函数建立第二套控制器；
  2. 严禁对历史动作进行无关的补丁式微调；
  3. 严禁在时间轴上硬编码特殊错误帧；
  4. 严禁静默放宽 `joint_limits.py` 等测试与生理阈值；
  5. 严禁数学截断或误差隐藏后伪报行为成功；
  6. 严禁绕开 `WholeBodyController` 直接操作骨骼；
  7. 严禁直接覆盖历史正确基准场景；
  8. 严禁擅自删除 Legacy 资产或历史基准模块。
* **统一测试执行与退出码铁律**：每次任务验证必须统一调用 `python tests/run_test_suite.py --tier <tier>` 或 `.\run_tests.ps1` 进行自动化回归。任何子测试非零退出码或日志中出现失败标记，绝对一票否决，严禁提交代码。
* **目视验收防线分离**：自动化测试通过仅标定为 `Automated Pass`，涉及动画自然度与视觉表现的必须由用户在 Blender 中目视检查后方可最终关闭任务。
* **架构偏差事前报批**：发现架构不一致或确需调整架构时，必须暂停开发并向用户提交书面变更报告，获得用户明确批准并录入 `DECISIONS.md` 后方可实施。
